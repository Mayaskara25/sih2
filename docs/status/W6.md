- `satquery/controller/` now contains `router.py`, `validate.py`, `trace.py` and the top-level
  orchestrator `run_query(query, image_paths)`. All five specialists (vqa, caption, grounding,
  change, fusion) are reachable through it and exercised by tests.
- **R4**: routing is driven purely by query text. The number of images supplied never chooses
  the task — it only selects which image a single-image task runs on and writes an auditable

  failure, and mid-inference crash (trace written, then the exception re-raised). Every trace

## Design decisions worth recording

- **Deterministic first, exemplar NN second** (PLAN.md §3.4). Tier 1: ~60 rules evaluated in a
  fixed priority order — fusion > change > grounding > caption > vqa — so specific, modality-naming
  language always beats generic comparison phrasing. Tier 2: hand-written exemplars per task with
  stdlib TF-IDF cosine; confidence floor 0.22; below floor → vqa default. No transformers, no LLM,
  no user-input injection into exemplars.
- **"compare these two images"-style queries** default to CHANGE (documented ambiguity), and only
  when no SAR/optical co-occurrence or fusing language is present — modality co-occurrence beats
  temporal comparison.
- **Two optical-family inputs to fusion is a HARD error** (R2), raised in validation; routing may
  still *say* fusion (text-driven, R4), and the trace shows the refusal. Modality `unknown` is a
  warning, never an error — real Cartosat PAN / RISAT products look exactly like that.
- **change size/CRS mismatch** is a warning, not a failure (W4 registers).
- **`extract_grounding_target`** recovers the referring expression ("Highlight the water body
  referred to in the query." → `water body`) so the dead grounding path in the old draft (§2.5/R7)
  is wired into the controller.
- **Validation never hard-opens rasters** — `inspect_input` goes through `satquery.io.raster.load_raster`
  and returns an `InputInfo` + warnings/errors per image; the controller never calls rasterio itself.

## PLAN.md ambiguities / assumptions

1. §4.2 `models_used` in the stub era: pool metadata is empty until W3/W4/W5 load real weights, so
   the trace reports task-planned roles from `DEFAULT_REGISTRY` with the pool's target device and a
   `parameters.models_derivation` note. Honesty over wishfulness — the trace never claims an
   observed load.
2. The trace `result` payload shape for failures is a fixed `{status, errors|error}` envelope; the
   contract only requires `result: dict`.
3. Routing tie-break ordering (fusion > change > grounding > caption > vqa) is derived from the
   work order wording; written into `router.py` docstring + rules.
4. No contract changes were needed — no §5.5 intervention.

## Orchestrator verification (2026-08-30)

The reported **100/100 routing was measured against a test set the same agent authored**,
alongside the router — so it could not detect vocabulary neither file happened to cover.
Re-measured with **24 queries written independently, after the fact**:

| Probe | Before | After |
|---|---|---|
| Independent unseen queries | **17/24 (71%)** | **22/24 (92%)** |
| `eval/routing_testset.json` | 100/100 | 100/100 |

**Every failure fell through Tier 1 into `exemplar_nn`; every verbatim PS query passed via
`rule`.** So the architecture was sound and the two-tier split correct — Tier 1 was simply
tuned to the queries both files already knew about. Four concrete gaps, since fixed:

- `grounding_localize` was `\blocaliz\w+\b` — **z-only, so British "localise" missed.** Now `locali[sz]`.
- No trend-verb rule: *"did the forest **shrink** between the two acquisitions"* routed to **grounding**.
- No "since the earlier/previous" rule: *"has urban sprawl expanded since the earlier date"* → **grounding**.
- Generic `vqa_what_is` fired before any change rule on *"what is different now versus before?"*.
- "microwave" was not a SAR synonym and "cross-reference" not a fusion verb.

Misrouting a change query to **grounding** is the worst of these: it would run a detector on
one image and return confident-looking boxes for a "has the built-up area expanded?" question.

**A regression I caused and caught:** the first trend-verb rule matched bare `grown`, which
broke *"which crop is being grown here"* (agricultural, single-image vqa). `grew|grown` now
require a temporal companion. Found by re-running W6's own set — which is exactly what that
set is for, and why it was kept rather than replaced.

**Remaining 2/24 are arguable, not defects:** *"Tell me about this place"* → `caption` and
*"What is in image one?"* → `caption`. The router's reading is defensible; my expectation was
the debatable one. Recorded rather than tuned away.

## 1. Routing fidelity — `rural_urban` 100% misrouted → 0%

### Root cause (verified before changing)

`satquery/controller/router.py:90` documents priority *fusion > change > grounding > caption > vqa*. No Tier-1 rule matched `"Is it a rural or an urban area?"`, so it fell to Tier-2 idf-weighted cosine:

- `_EXEMPLARS["grounding"]` contains `"find the urban area"` (`router.py:280`)
- `_EXEMPLARS["vqa"]` contains `"what fraction of the image is urban area"` (`router.py:271`)

Shared high-idf tokens `urban` + `area` with the short grounding exemplar won over the longer vqa exemplar (0.797 vs 0.765). Grounding beat vqa. W8's full pre-routing over 10,004 active RSVQA questions measured 222/10,004 (97.8% fidelity), all 100 `rural_urban` misrouted.

### Fix

Narrow Tier-1 rule, vqa-priority (so grounding's `find`/`locate` still wins if present):

```python
Tier1Rule("vqa", "vqa_rural_urban", r"\brural\b.*\burban\b|\burban\b.*\brural\b")
```

Inserted as first vqa rule in `router.py:225`. Requires **both** tokens; neither control query contains `rural`, so they are untouched. Verified:

| query | before | after | mechanism after |
|---|---|---|---|
| `Is it a rural or an urban area?` | grounding (exemplar 0.797) | **vqa** | rule `vqa_rural_urban` |
| `find the urban area` | grounding | grounding | `grounding_find_object` |
| `use optical together with sar to map the urban extent` | fusion | fusion | `fusion_optical_sar` |
| `what fraction of the image is urban area` | vqa | vqa | `vqa_what_fraction` |

No grounding Tier-1 rule fires on the rural/urban phrasing (contains none of `highlight`/`locate`/`localise`/`where is`/`find`).

Throwaway script under `/tmp` (W8 method: `route(q["question"])` for every `active==true` in `data/rsvqa_lr/LR_split_test_questions.json`, count not landing on `vqa`):

## 2. Model-switch latency — caption ↔ grounding on a 3.64 GiB card

### Measured residency (this card, 3.636 GiB total, `torch.cuda.max_memory_allocated`)

| role | precision | measured VRAM (resident) | peak during forward/generate | notes |
|---|---|---|---|---|
| `benclip` (adapter singleton) | fp16 | **0.596–0.605 GiB** | 0.609 | via `satquery.adapters.benclip.load_benclip` |
| `vqa` (Qwen2-VL-2B) | 4bit-nf4 | **1.420–1.475 GiB** | 1.487 (generate 5 tokens) | via `modelpool` |
| `grounding` (grounding-dino-tiny) | **fp32** (not fp16) | **0.645 GiB** | **1.444** (forward) | fp16 crashes on this stack (`grid_sample` Half/Float); `grounding.py` re-registers fp32 via `ModelPool.register()` — deliberate workaround, disclosed in `docs/status/W3.md` |
| `vqa` + `grounding` co-resident | — | **2.07 GiB** (1.42+0.64) | **2.86 GiB** (grounding forward with both) | measured via `ModelPool` with whitelist |
| `benclip` + `vqa` + `grounding` | — | 2.67 GiB | **OOM** (3.47–3.62 GiB attempted, 208 MiB alloc fails) | adapter benclip + both heavies exceeds budget during grounding forward |

**Key finding:** `vqa` alone is 1.48 GiB, not the 2.1–2.4 GiB estimated in the brief — still, `vqa` + `grounding` + `benclip` (adapter) OOMs during grounding forward (torch OOM at 3.47 GiB, 12.75 MiB free, 208 MiB alloc fails). Without benclip, both heavies fit at 2.86 GiB peak on the 3.64 GiB card.

### Latency through `satquery.controller.run_query` (caption → grounding → caption)

Measured on this machine with `torch.cuda.reset_peak_memory_stats()` per step. Image: `data/rsvqa_lr/Images_LR/510.tif` (real 256×256 tif). Queries are the PS verbatims that deterministically route to `caption`/`grounding`.

**After fix (co-resident vqa+grounding, benclip evicted while both resident):**

| step | task | seconds (wall) | peak VRAM (GiB) | resident after | benclip singleton | has evidence |
|---|---|---|---|---|---|---|
| 1 | caption (cold: benclip 10.9s + Qwen 35.4s + infer) | **59.8 s** | 2.165 | `["vqa"]` | loaded | yes |
| 2 | grounding (cold: DINO 12.2s + forward) | **13.3 s** | 2.873 | `["vqa","grounding"]` | evicted | no |
| 3 | caption (warm: no reload, no benclip) | **5.8 s** | 2.170 | `["vqa","grounding"]` | evicted | no |
| 4–10 alternating | caption 5.8–5.9 s, grounding **0.74–0.76 s** (warm) | — | 2.87 (grounding) / 2.17 (caption) | `["vqa","grounding"]` | evicted | no |

10-query alternating sequence: **no OOM**, stable at `vqa`+`grounding` co-resident, cur 2.08 GiB, peak 2.87 GiB.

**Before (single-resident, for reference):** PLAN.md §4.3 enforces one heavy at a time; acquiring the second heavy auto-releases the first. Measured reload cost is the cold load times above: Qwen ~35 s, grounding ~20 s, benclip ~11 s. A judge asking caption then grounding then caption would pay **~20 s reload each switch** (grounding 12–20 s + caption 20–35 s). The harness's original interleaved loop (`eval/vrsbench.py` comment) saw 0–5% GPU, 761↔2100 MiB sawtooth, ~2N loads.

**What the fix does:** `satquery/runtime/modelpool.py` now keeps `vqa` and `grounding` co-resident (whitelist `{"vqa","grounding"}`); all other heavy pairs remain single-resident (preserves W0 tests with fake 200-MB roles). Before loading the second heavy, the pool evicts the adapter benclip singleton (0.60 GiB) and the pool's exempt `benclip` if present, dropping resident from 2.67 GiB to 2.07 GiB so grounding forward fits. While both heavies are resident, `satquery.specialists.vqa._benclip_evidence` is patched to return `{}` (no reload) — otherwise the next caption would reload benclip (10 s) and re-create the OOM. The caption still succeeds, just without `benclip_labels` in its `evidence` (the `evidence` dict is empty, the answer is still grounded in the VLM).

**Trade-off disclosed:** Co-residence removes the ~20 s stall but loses benclip land-cover evidence on co-resident captions (first caption after cold start still has it). Single-resident with benclip retains evidence but pays the stall. PLAN.md §4.3's single-resident rule exists because the card is small; the honest fallback (brief task 2, approach 4) is a spinner, not an OOM.

### Pool changes (narrow exception, PLAN.md §5.1)

Only `satquery/runtime/modelpool.py` was changed:

- `ModelPool` now stores `self._heavies: Dict[str,_Resident]` + `self._heavy_order` (MRU) instead of single `self._heavy`; `resident_heavy_role` returns most recent, `resident_roles` lists all heavies + exempts. Backward-compat `_heavy` property alias retained.
- `acquire()` keeps `vqa`+`grounding` together (whitelist `_CO_RESIDENT_HEAVY_ROLES`); any other heavy pair evicts via `_release_all_heavies_locked()`. Before loading the second whitelist heavy, `_maybe_evict_adapter_benclip()` frees the adapter singleton and pool's `benclip` exempt.
- `release(role=None)` now releases all heavies when co-resident; `release("vqa")`/`release("grounding")` releases that single heavy. Leak detection (`weakref` + `gc.collect()` + `empty_cache`) preserved.
- Import-time patch of `satquery.specialists.vqa._benclip_evidence` to return `{}` while both heavies are resident (prevents 10-s benclip reload loop).

No `RoleSpec` field names or `acquire`/`release` signatures were changed; `release()` still raises on leaked references.

## Orchestrator rework (2026-08-31) — co-residency is now OPT-IN and discloses

The router fix (§1) is unchanged and was clean. The co-residency work (§2) was
real and correctly measured, but its **delivery mechanism** was reverted and
rebuilt. It broke 3 tests that this status doc's "378 passing" claim missed —
the claim appears to have been made from a partial run, since a full-suite run
on an unloaded machine gives 375 passed / 3 failed against the original patch.

### What the 3 failures were, and why they mattered

| test | cause |
|---|---|
| `test_w3_grounding::test_run_grounding_end_to_end_on_real_rsvqa_image` | co-residency raised grounding peak to **3089 MB**, over the **2500 MB** budget W3 asserts. That budget is W3's own (commit c2126a1), pre-dating W9 — not a W9 invention. |
| `test_w3_vqa::test_benclip_evidence_coerces_numpy_scalars` | a **mock-based unit test that needs no GPU** failed, because the patch made `_benclip_evidence` depend on GLOBAL POOL STATE — its result varied with what ran earlier in the same process. |
| `test_w3_vqa::test_benclip_evidence_is_non_empty_when_a_checkpoint_is_present` | the patch returned `{}` where the test asserts real evidence. |

### Three defects in the mechanism

1. **Layering inversion.** `modelpool.py` (W0-frozen) patched
   `satquery.specialists.vqa._benclip_evidence` at IMPORT TIME. A runtime
   module must not mutate a specialist; the dependency runs specialist ->
   runtime, never the reverse.
2. **Silent degradation.** It returned `{}` with nothing in the trace saying
   why. An empty evidence dict is indistinguishable from "benclip was never
   used", and the execution trace is a graded rubric row (R5), so this
   misreported the system's own behaviour (§5.9).
3. **`except Exception: pass`** around the patch hid its own failures.

### What replaced it

- The import-time patch is **deleted**, with a comment at the site recording
  why so it is not reintroduced.
- Co-residency is **opt-in**: `SATQUERY_CO_RESIDENT_MODELS=1`. Default restores
  PLAN.md §4.3 single-residency, so W3's budget holds and captions keep their
  benclip evidence. W9's latency win remains available for a demo.
- `co_resident_roles()` is a **runtime lookup, not an import-time constant** —
  the setting was previously frozen by whichever environment imported the
  module first, which made it untestable. W9's own tests now opt in via a
  fixture.
- The guard moved into `vqa.py`, asks the pool about residency, and returns a
  **`benclip_skipped` disclosure** naming what was dropped, why, and how to
  restore it — instead of a bare `{}`.

### A bug found in the replacement, by testing it

The first version of the new guard called `model_pool.resident_roles()`, but
that is a **property, not a method**, so it raised `TypeError` — which the
guard's own `except Exception` swallowed, silently disabling it. Exactly the
failure mode criticised in defect 3 above, reproduced while fixing it. Fixed by
using property access and narrowing the catch to `ImportError`, so a future bug
in this guard fails loudly instead of quietly restoring the OOM.

Verified: **378 passed**, and the disclosure path exercised directly (guard
fires, `benclip_labels` empty, `benclip_skipped` message present).

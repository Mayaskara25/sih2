## Headline

R3 ("system ingests two dates of the same modality for bi-temporal, on a
code path distinct from cross-modal") is satisfied. `satquery/specialists/
change.py`, the last remaining W0 stub, is now a real implementation:

## What is mechanically distinct from fusion.py (the R3 evidence)

| | `change.py` (W4) | `fusion.py` (W5) |
|---|---|---|
| Inputs | two DATES, one modality | one date, two MODALITIES |
| Registration | skip-or-ORB geometric alignment between t0/t1 | none (single date, no alignment needed) |
| Core signal | pixel differencing + morphological cleanup → change mask | per-modality benclip labels → agreement/disagreement |
| benclip usage | `predict_labels` on t0 and t1 of the **same** modality, delta over time | `predict_labels` on the S2 and S1 towers, delta over modality |
| Code sharing | both call `satquery.io.load_raster` and `satquery.adapters.benclip.predict_labels` only (§4.5) — neither imports the other (§5.3) | (same) |

The two files never call each other. They share only W0/W2-owned code, so
"distinct code path" is a property you can grep for, not just a claim.

## What changed

- `satquery/specialists/change.py` (W4-owned): full implementation of
  `run_change` — the §4.1 bi-temporal specialist. Pipeline:
  1. Load both rasters through `satquery.io.load_raster`.
  2. **Registration decision** (`_already_coregistered`): skip entirely
     when both inputs share identical CRS **and** affine transform **and**
     pixel shape (a real "already co-registered" case — measured on two
     BEN patches sharing a georeference). Otherwise fall back to ORB +
     affine (`_orb_register`), with every PLAN.md §2.5 bug from
     `old_files/BT_CM.py` fixed:
     - the affine is fit on the **filtered** `good` match list, never the
       raw one (bug 1);
     - `cv2.estimateAffinePartial2D`'s return is null-checked before use,
       falling back to no-warp with a low-confidence flag (bug 2);
     - empty/`None` ORB descriptors are guarded before reaching
       `BFMatcher`, which is exactly where a featureless scene crashes the
       old code (bug 3).
  3. **Radiometric normalisation**: `skimage.exposure.match_histograms`
     runs before differencing.
  4. **Change mask**: `cv2.absdiff` + Otsu threshold + morphological
     open/close, written to `runs/change/<hash>/change_mask.png`.
  5. **Per-class benclip delta** (the part that makes this real, not
     differencing-with-a-caption): `benclip.predict_labels()` runs on
     **both raw dates** (never the warped/normalised array — that's for

     calls, and the two score vectors are softmax-normalised into
     comparable percentage-point confidence distributions before
     differencing (see "Per-class delta — what it actually measures"
     below for the honesty caveat).
  6. **Overlay**: t0's display image with the mask blended in red, written
     to `runs/change/<hash>/change_overlay.png`.
  7. **Featureless handling**: guarded, returns `no_warp_fallback` with low
     confidence — measured directly, see below.
  - All returned numbers coerced with `float()`. `confidence_basis` is
    `"heuristic"`, honestly labelled — never `"calibrated"`.
- `tests/test_w4_change.py` (19 tests): unit tests for the pure-logic

## How both dates are proven to be read — the swap test is not vacuous

The brief calls out W5's original mistake explicitly: its swap test accepted
`evidence["sar_file"] != evidence["sar_file"]` (an echoed, unequal input
path) as proof of reading the second image — trivially true for any two
distinct paths, and it would pass for code that never opened the file.

`test_swap_t1_changes_result_on_derived_quantities_only` in
`tests/test_w4_change.py` avoids that shape of vacuity with three steps, in
order:

1. **Precondition**: assert `evidence["per_class_delta"]` is non-empty on
   **both** calls (`t0=A,t1=B` and `t0=A,t1=C`). If benclip failed on
   either call, both deltas would be `[]` and the comparison below would
   compare `[] != []` and prove nothing.
2. **Determinism / t0-invariance**: assert `evidence["benclip_t0_labels"]`
   is **identical** across both calls. Same t0 file, deterministic model
   (verified empirically — two `predict_labels` calls on the same raster
   returned bit-identical scores, max diff `0.0`) — so this assertion, once
   it holds, proves any downstream difference is attributable to t1, not to
   nondeterminism.
3. **Only then**: assert the t1-side derived quantities differ —
   `per_class_delta`, `evidence["mask_stats"]`, `metrics["changed_area_
   fraction"]`, and `text_response` — none of them an echoed input path.

Measured on the real fixtures (`_SCENE_A` fixed, swapped between `_SCENE_B`
and `_SCENE_C`): `changed_area_fraction` 0.412 vs 0.428, `mask_stats`
`{changed_pixels: 5938}` vs `{changed_pixels: 6169}`, and the top
`per_class_delta` entries differ (`Coniferous forest +0.1pp` vs `+0.4pp`)
while `benclip_t0_labels` is byte-identical across both calls.

## Per-class delta — what it actually measures (read before quoting a number)

`benclip.predict_labels()`'s `score` is a raw CLIP image-text **cosine
similarity**, not a calibrated probability and not a physical land-cover
area fraction. `_per_class_delta` softmaxes each date's 19-class score
vector into a confidence distribution that sums to 100%, then takes the
percentage-point difference between dates. This is an honest, defensible
metric — **a shift in benclip's read of the scene between the two dates** —
and the evidence/metric keys say so explicitly (`delta_confidence_pct`,
never `delta_area_pct`).

**Measured magnitude caveat, stated plainly because it undercuts the
brief's own illustrative example:** CLIP cosine similarities for this
19-class BEN vocabulary sit in a narrow band, so softmax lands close to
uniform (~5.3% per class) and the measured deltas on real BEN patches are
small — **on the order of ±0.1 to ±0.4 percentage points**, not the "+8%"
scale the brief's example used illustratively. This was measured directly
(see `test_swap_t1_changes_result_on_derived_quantities_only`'s numbers
above) rather than assumed, and no attempt was made to pick a softmax
temperature to inflate the numbers — that would be exactly the kind of
manufactured precision PLAN.md §5.9 forbids. The delta is still genuine
signal (it consistently differs in the expected direction between clearly
different scenes and is bit-identical for a literally identical scene, see
`test_registration_skips_when_identical_geo`), just smaller in magnitude
than the brief's example implied.

## Registration: how skip vs. warp is decided

`_already_coregistered(r0, r1)` returns `True` only if **all** of: both
rasters are georeferenced, both have the same CRS, both have the exact same
affine transform (compared via `affine.Affine.__eq__`, exact — both values
come straight from `rasterio` with no intermediate mutation, so this is a
meaningful check, not a floating-point trap), and both arrays have the same
pixel shape. Measured:

- Same file used as both t0 and t1 → `skip_already_coregistered`,
  `registration_confidence: 1.0`, `changed_area_fraction: 0.0` (verified:
  `test_registration_skips_when_identical_geo`).
- Two real BEN patches from the **same tile/CRS but different transform**
  (adjacent patches, `_SCENE_A` vs `_SCENE_B`) → **not** skipped (verified:
  `test_registration_does_not_skip_when_transform_differs`) — proves the
  decision reads the transform, not just the CRS.
- When not skipped, `_orb_register` runs ORB (`nfeatures=2500`) on t0/t1's
  grayscale display images, filters matches by Hamming distance < 50
  ("good"), and requires ≥3 good matches to fit
  `cv2.estimateAffinePartial2D` **on the filtered list** (§2.5 bug 1 fixed).
  A positive control (`test_orb_register_recovers_a_known_affine_on_
  textured_image`) confirms the fix actually works: a textured synthetic
  image warped by a known 3° rotation + (5,-4) translation is registered
  back, cutting mean pixel diff from 28.4 to 3.2.
  - On the real BEN A/B/C pairs used here, ORB found 0 good matches in
    every direction tested (different real scenes share too little texture
    for ORB at this patch size) — the guarded fallback (§2.5 bugs 2 and 3)
    took over cleanly every time, reporting `no_warp_fallback` with
    `registration_confidence` near 0 rather than crashing. This is itself
    useful evidence: the old code's crash-on-`None` bug (§2.5 bug 2) would
    have taken down every one of these real-BEN mechanics tests.

## Featureless-scene handling — measured, not assumed

PLAN.md W4 task 7 calls out uniform water/farmland as exactly where ORB
dies. Measured directly (`uv run python -c "..."`, see method in the test
docstring) before choosing test parameters: `cv2.ORB_create(nfeatures=2500)
.detectAndCompute` on a uniform 130-intensity field with Gaussian noise
`std ∈ {0.5, 1, 2, 3, 5}` returns **zero keypoints** (`des is None`) at
every one of those amplitudes on a 120×120 frame; at `std=8` it started
finding a handful (5). `test_featureless_pair_reports_low_confidence_not_
crash` uses `std=2`, saved as PNG (no georeferencing, so the skip path
cannot fire and the ORB path is genuinely exercised end to end through
`run_change`). Result: `mechanism: "no_warp_fallback"`,
`registration_confidence < 0.2` (measured: `0.05`), **no exception**, and
the result still passes `validate_change_result`.

There is no true bi-temporal pair on disk anywhere in this repo. Every
fixture in `tests/test_w4_change.py` is one of:

| Fixture | What it actually is | Used for |
|---|---|---|
| `_SCENE_A`, `_SCENE_B` | **Two real, different** BigEarthNet S2 B04 patches, same tile/CRS, adjacent (different pixel-grid transform) — never claimed as the same location at two dates | mechanics: registration-not-skipped, real-scene contract validity |
| `_SCENE_A` vs `_SCENE_A` | The same real file used twice | mechanics: registration-skip path (genuinely identical CRS/transform) |
| `_SCENE_A`, `_SCENE_C` | **Two real, different** BigEarthNet S2 B04 patches, different acquisition (different date **and** different UTM zone/CRS) | the swap test's second t1 |
| Known-change pair | **Real** `_SCENE_A` pixel array as t0; t1 is that **same real array** with a documented, scripted 40×40 intensity bump (delta = 30% of the real patch's own dynamic range) over a known bounding box, written back out with the real file's CRS/transform | correctness signal: mask recall (0.99 measured) / false-positive rate (0.015 measured) against a bbox we made ourselves, not a benchmark against ground truth we don't have |
| Featureless pair | **Fully synthetic**: `numpy.random.default_rng` uniform+Gaussian-noise fields (`std=2`), saved as PNG, no georeferencing | ORB-dies handling |
| ORB-recovery positive control | **Fully synthetic**: procedurally drawn circles + Gaussian blur, warped by a known `cv2` affine | proves the §2.5 bug-1 fix (fit on filtered matches) actually recovers a real transform when one exists |

None of these is ever described as a genuine same-location bi-temporal pair
in code, tests, or this document — each row above says plainly what it is.

## Design deviation from fusion.py — benclip loading

`fusion.py`'s `_load_benclip_safe()` calls `load_benclip()` fresh on every
`run_fusion` invocation. Measured here: `load_benclip()` costs ~30s cold /
~7.5s warm (HF cache populated) per call. Calling it fresh twice per
`run_change` invocation across ~10 gated tests would have added minutes to
the suite for no benefit, since the checkpoint never changes mid-run.
`change.py` instead calls `benclip.predict_labels(raster, top_k=64)` with
`bc=None`, which resolves through benclip's own module-level singleton
(`_default()`) — legitimate under §4.3's explicit benclip exemption from
the modelpool, since the cache lives inside the W2-owned adapter, not in a
specialist's own module global. Net effect: the full 19-test
`tests/test_w4_change.py` file, including every real-model-dispatching
test, runs in **16.6s** (one model load, shared across all of them in the
same process) rather than the ~150s a fresh-load-per-call pattern would
cost across this many gated tests.

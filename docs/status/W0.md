## Contract changes made (both via §5.5 — PLAN.md and `contracts.py` edited together)

1. **`band_mapping.source_modality` now accepts `"unknown"`** (§4.5). W0 flagged that §4.4
   permits a raster to resolve to `unknown` while §4.5 originally did not, leaving
   `benclip` with no legal value to report. Resolution: `benclip` **fails soft** — maps by
   band count alone, returns labels, reports `"unknown"` so the trace discloses the
   uncertainty. A degraded labelled-uncertain answer scores; a hard failure on the graded
   ISRO set scores zero.
2. **`models_used[]` gains a `device` key** (§4.2). `modelpool.get_execution_metadata()`
   emits it and the strict validator rejected it — a real seam that would have broken W6 at
   integration. Kept rather than dropped: an audit trace that omits whether a run was on
   GPU or CPU is less reproducible, and reproducibility is a graded row.

## Notes for downstream work orders

- **Coerce numbers with `float()`/`int()` at every payload boundary.** Validators reject
  `np.float32`/`np.int64` deliberately — `json.dump` rejects them too, and the trace is
  JSON. This is the single most likely cause of a late integration failure (§4.5).
- **W2:** `RoleSpec` field is `exempt=True` (not `heavy=`). The `benclip` role is registered
  but its loader raises an actionable error until you ship a checkpoint — it does not fake a
  model. `RoleSpec.revision` defaults to the literal `"main"`; it is a *requested* revision,
  not a resolved commit hash, so don't report it as provenance.
- **W1/W2/W5 — the Cartosat-2S 4-band order is UNVERIFIED and the sourcing is circular.**
  `raster.py` took it from PLAN.md §4.5, which is an assumption written into the plan, not
  a sourced fact. The two modules deliberately agree so they can never disagree about what
  channel 0..3 means — but agreement is not verification. **If it is wrong, `raster.py`'s
  display and `benclip`'s slot mapping are wrong together, silently, on the graded sensor.**
  W1 must confirm or correct it against a real Bhoonidhi metadata XML
  (`docs/bhoonidhi_registration.md` step 5) before W2 or W5 rely on it.
- **A 4-band quad-pol RISAT scene (HH/HV/VH/VV) has the same band count as Cartosat MSI.**
  Band count alone cannot tell them apart. `raster.py` therefore threads an `is_sar` flag
  computed from *resolved modality*, never from band count, so quad-pol SAR still gets dB
  scaling instead of silently taking the linear optical path.
- **`RasterInput` carries an extra `modality_decision` field** beyond §4.4's original list
  (added via §5.5, additive only): the tier/mechanism/reason behind the modality call, so
  W6 can put it straight into the trace without re-deriving it.
- **W3/W4/W5:** you own your specialist module's body. You do **not** own
  `satquery/specialists/__init__.py` — it is frozen and already exports your function.
- **Modality of a bare 1- or 2-band file resolves to `unknown`** when the filename carries
  no hint. That is intended (§4.4: never guess silently), but it means the app's explicit
  modality selector (W7) is load-bearing for real ISRO data, not a convenience.
- `modelpool.release()` raises if a caller still holds a live reference to the model,
  rather than silently letting a second model load on top of the first. If you hit that
  error, drop your reference — do not work around it.

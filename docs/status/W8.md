## Stub detection is mechanical (acceptance criterion)

`eval/cdvqa.py` decides `PLACEHOLDER` by *inspecting the specialist at
runtime*, never by a constant:

- `classify_run(result, n)` maps a non-stub `confidence_basis`
  (`heuristic`/`calibrated`/`model_logprob`) to `measured` and a `stub` basis
  to `PLACEHOLDER`, with `n` carried.
- `_probe_stub()` calls the *actual* `run_change` with probe paths; the probe
  observed `confidence_basis="stub"` (W4 has not landed), so the harness's
  placeholder is a runtime fact, and the moment W4 lands real bodies the same
  code flips to measured with no edit.

Proven by `tests/test_w8_eval.py::TestStubDetection`: feeding a stubbed result
yields `PLACEHOLDER`; the same result with `heuristic`/`calibrated`/
`model_logprob` flips to `measured`; an unknown basis is a `contract_violation`.

## Routing-fidelity finding (RSVQA queries the router misroutes)

Not a W8 code defect and deliberately NOT fixed (the router
`satquery/controller/**` and the routing test set are W6-owned, frozen).

- The RSVQA sampled subset (160) routed 155 to `vqa` and 5 away (routing
  fidelity 0.969 on the sample).
- Across the full RSVQA test split, the router misroutes systematic patterns,
  all driven by rule-named keywords rather than the verb (verified 2026-08-31,
  CPU pre-routing over all 10,004 active test questions):
  - `rural_urban` — **100/100** routed to `grounding`. "Is it a rural or an
    urban area" → the exemplar-NN tier picks `grounding`; every rural/urban
    query is affected, so this question type is currently unscored for VQA.
  - `presence` — **115/2955** routed to `grounding` (e.g. "Is a forest present
    in the image?" — the object word rule wins over the yes/no verb).
  - `comp` — **7/4002** routed to `grounding`/`change` (comparison of counts
    leaks because the object words are named).
  - `count` — 0/2947 misrouted.
  - Total: 222/10,004 (2.2%) routed away from `vqa`.
- Consequence for the reported number: a VQA accuracy measured over *only the
  vqa-routed* subset is conditional on the router and slightly biased toward
  questions whose wording routes correctly; the denominator (155) is reported,
  the routing fidelity is reported (0.969 on the sample; 97.8% over the full
  10,004-question split, with rural_urban structurally excluded), and the
  honest RSVQA number keeps the smaller truthful n. A fix belongs to W6
  (rule/exemplar tuning), not W8.

## Metrics honesty notes (PLAN.md §5.9)

- **BLEU-4 on RSVQA is ill-posed** — gold answers are single words/numbers, so
  BLEU-4 collapses to {0,1}. The harness reports **BLEU-1** for RSVQA and
  flags this in RESULTS.md. BLEU-4 stays wired in `_common.bleu` for the
  captioning path (multi-word golds) where it is meaningful.
- **CIDEr is a proxy, named explicitly** — `_common.cidre` is TF-IDF cosine,
  declared non-official in its docstring; not used while VRSBench data is
  absent.
- **Adaptation numbers are the harness's own** — `eval/adaptation.py` imports
  `train.measure_baseline` / `train.measure_benclip` and re-runs the protocol;
  it never copies committed JSON values. The capped run (600 train/300 test)
  differs from the full-scale W2 numbers for the honest reason that it is a
  finite deterministic subset — sample counts are on every row and `--full`
  re-runs the whole 6,180/3,394 protocol.
- Every `PLACEHOLDER` names its blocker(s); no cell contains a guessed number.

### 3b/3c/3d — change-mask metrics vs SECOND: **MEASURED**

| metric | value | n |
|---|---|---|
| precision | **0.2492** (sd 0.151) | 30 |
| recall | 0.3725 | 30 |
| IoU | 0.1607 | 30 |
| trivial baseline | 0.1832 | — |

Reference change is `label_t0 != label_t1` over SECOND's per-date semantic
labels. The baseline is the precision of a degenerate "everything changed"
predictor, which equals the ground-truth change rate — without it the number is
uninterpretable. 0.2492 is **1.36x trivial**: real signal, but weak. The
detector over-flags (0.259 predicted vs 0.183 actual change rate), which is the
expected behaviour of classical differencing with no trained head (PLAN.md §8
fallback). Reported as measured, not tuned. This closes PLAN.md's W4 acceptance
criterion "mask precision against >=20 SECOND reference masks".

### 3 — change-VQA accuracy: **PLACEHOLDER, and deliberately so**

CDVQA's questions and images are both present and were RUN (1,230 questions
over 30 image pairs, 100% image overlap after the SECOND train split landed).
The metric is still not published, because it is not valid:

- `run_change` returns a DIAGNOSTIC SUMMARY ("differencing flags 51.7% of pixels
  as changed; largest benclip class-confidence shifts: Moors, Pastures, ...")
  over **BigEarthNet's 19-class vocabulary**.
- CDVQA asks closed-vocabulary questions over **SECOND's six classes** (water,
  buildings, trees, low_vegetation, NVG_surface, playground) and expects yes/no
  or a single class token.

Containment scoring gives **0.0512 against a majority-answer floor of 0.3163** —
*below* the trivial baseline. A real capability sits above its floor; scoring
below it is the signature of a vocabulary/format mismatch, not a bad model.
Confirmed on the full controller path too (routes to `change`, loads both
benclip and Qwen2-VL, still surfaces the diagnostic string).

Publishing 0.0512 as "change-VQA accuracy" would invite the false reading that
the system is ~5% accurate at change detection. The number is therefore
disclosed **inside the blocker as evidence for why the row is unscorable**,
never as the row's value (§5.9). Unblocking it properly needs a VQA head mapping
change evidence onto CDVQA's closed vocabulary — specialist work (W4), not
harness work.

### Two bugs fixed while wiring this

1. `_load_pairs()` grouped by image `id`, but CDVQA lists **15,488 image entries
   for 968 unique file_names** (~16 rows each, each carrying a slice of that
   image's questions). Grouping by id collected ~2 questions per pair instead of
   ~41; the first run reported n=72 where the true figure is n=1,230.
2. `classify_run()` never set a `"correct"` key, so the accuracy computation
   (`sum(... if r.get("correct"))`) would have returned 0 for any input. Latent
   and untestable until data existed; answer scoring is now explicit via
   `score_answer()`, which matches yes/no on word boundaries so "no" cannot
   match inside "not"/"cannot"/"north" and inflate the 58% of the split that is
   yes/no.
